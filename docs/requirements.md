# 要件定義書 - Pico Ducky実験(キー注入とキーロガーの仕組み学習)

このファイルはREADME.mdとは別に、本プロジェクトの要件をまとめたものです。

## 1. 目的
Raspberry Pi Pico WHをUSB HIDキーボードとして振る舞わせ(いわゆる「Pico Ducky」/BadUSB)、
攻撃者がUSB経由で任意のキー入力を注入できてしまう仕組みと、それを起点にキーロガーが
成立する過程を実際に体験することで理解する。あわせて、その防ぎ方(検知・防御策)を学ぶ。

**本プロジェクトは教育・防御目的の実験専用であり、攻撃行為を目的としない。**

## 2. 対象ユーザー
自分自身(学習目的)。実験は自分が所有・管理するWindows機、または隔離VM上でのみ行う。

## 3. 利用範囲(必ず遵守すること)
- 実行対象は自分が所有・管理するWindows機/隔離VMに限定する。他人のPC・共用PC・業務PCへの
  無断実行は絶対に行わない(不正アクセス禁止法・不正指令電磁的記録に関する罪に抵触しうる)。
- ネットワーク送信・外部送信を行う機能は実装しない。
- ペイロードは自動ループさせず、挿すたびに1回だけ動作する設計とする。

## 4. 機能要件
| ID | 内容 |
|---|---|
| F1 | Pico WHがCircuitPython上でUSB HIDキーボードとして認識されること |
| F2 | Pico WHをUSB接続後、5秒待機してから固定文字列を1回だけタイプすること(暴発防止の安全マージン) |
| F3 | タイプ後は自動的に停止し、ループしないこと(抜き挿しするまで再実行されない) |
| F4 | PC側キーロガーデモ(`tools/keylogger_demo.py`)は手動起動・手動停止(Ctrl+C)でき、記録は
      ローカルの日時付きログファイルにのみ書き込むこと |
| F5 | キーロガーデモは起動時・停止時にコンソールへメッセージを表示し、確認後はログファイルの
      削除を促すこと |

## 5. 非機能要件(ガードレール)
| ID | 内容 |
|---|---|
| N1 | ペイロードは自動ループ・常駐化させない。挿すたびに1回きりの動作とする |
| N2 | ネットワーク送信・外部送信・永続化(自動起動設定の書き換え等)を行う機能は一切実装しない |
| N3 | キーロガーデモはネットワーク機能を持たず、ローカルファイルへの記録のみとする |
| N4 | 実行対象を自分が所有・管理するWindows機/隔離VMに限定する旨を、コード・READMEの両方に
      明記する |
| N5 | 挿入直後の5秒待機を必須とし、暴発防止の安全マージンとして削除・短縮しない |

## 6. ハードウェア構成
- ボード: Raspberry Pi Pico WH
- ファームウェア: CircuitPython(MicroPythonから変更。USB HIDキーボードのエミュレートに
  `adafruit_hid`ライブラリを使用するため)
- 配線: 不要。USBケーブルでWindows機に接続するのみ(MFRC522・サーボ等の外部配線はなし)

## 7. 開発環境・ファイル受け渡し
- コード作成: Mac上のCursor(Claude Code)
- CircuitPythonファイルの配置: Windows機のExplorerで`CIRCUITPY`ドライブへ直接コピー
  (Thonnyでの転送操作は不要。Thonnyは注入デモの入力先アプリとして使用する)
- 両者はGitHubリポジトリ(`https://github.com/akki-secure/RaspberryPi.git`)経由でファイルを
  受け渡す(Mac側でpush→Windows側でclone/pull)

## 8. ログ設計
### Pico側(`src/pico_ducky/code.py`)
CircuitPythonのUSBシリアルコンソール(Thonny等で確認可能)に、可能な範囲で以下を出力する。
- 起動時: 待機開始のprint出力
- タイプ完了時: 完了のprint出力
- エラー時: 例外内容のprint出力

### PC側キーロガーデモ(`tools/keylogger_demo.py`)
- 記録先: 実行ディレクトリの`keylogger_demo_<日時>.log`(gitignore対象)
- 記録内容: 押下時刻ISO形式 + キー文字(特殊キーは`[Key.xxx]`表記)
- コンソール出力: 記録開始・記録先ファイル名・停止方法・記録終了・ログファイル削除の案内

## 9. ガードレール(再掲・実装レベル)
- Pico側コードにループ処理を入れない(1回タイプしたら終了)
- キーロガーデモにネットワーク送信コードを含めない
- 両スクリプトの冒頭コメントに、利用範囲(自分のWindows機/隔離VM限定)を明記する
- 生成されたログファイルは`.gitignore`で除外し、誤ってコミットされないようにする

## 10. 防御の観点(学習ゴール)
本実験を通じて、以下の防御の考え方を整理する(詳細はREADME.mdの「防御方法」章を参照)。
- USB HID機器は「キーボードです」と名乗るだけで信頼されてしまう(HID規格の性質)
- Windowsのグループポリシー/USBデバイス制御ソフトによる未知デバイスの接続制限
- 「USBメモリのはずがキーボードとしても認識される」複合デバイスの挙動を検知するエンドポイント
  保護製品の活用
- 信頼できないUSB機器を安易に挿さない、という物理的な運用ルールの徹底

## 11. テスト方針
- 本実験のコードはCircuitPython専用APIおよびOSのキーボード監視APIに強く依存し、
  ハードウェア/OS非依存のロジックがほとんどないため、PC側の自動テスト(pytest)対象は
  現時点で設けない。
- 静的解析は`ruff check src tests`をPC側で実行する(`lib`配下は外部OSSライブラリのため対象外)。
- 実機動作(USB挿入→キー入力注入、キーロガーデモの記録)はハードウェア/OS依存のため
  自動テストできない。以下の手動確認チェックリストに従う。

### 手動確認チェックリスト
1. CircuitPythonをWindows機でPico WHに書き込む(`RPI-RP2`へ`.uf2`をコピー)
2. `src/pico_ducky/code.py`を`CIRCUITPY`ドライブ直下へ、`lib/adafruit_hid/`を
   `CIRCUITPY/lib/`へExplorerでコピーする
3. Windows機でThonnyを起動し、新規ファイルのエディタにカーソルを置く
4. Pico WHをUSB接続し、5秒待機後にThonnyのエディタへ固定文字列が自動入力されることを確認する
5. `tools/keylogger_demo.py`を実行し、手動でキーを押して記録されること、Ctrl+Cで停止できる
   ことを確認する
6. 確認が終わったら、生成されたログファイル(`keylogger_demo_*.log`)を削除する

### テスト実行時間の目安
`pytest`は通常数秒以内に完了する規模。**30分以上かかっている場合はフリーズしている可能性が
高いため、実行を止めてユーザーに確認すること。**
